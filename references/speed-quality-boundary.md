# 速度与质量边界

## 处理原则

提速只减少重复工作，不改变最终素材质量：

- 低分辨率预览帧只用于定位候选时间点；最终人物图和场景图必须从原视频重新提取。
- 不降低原视频截图的宽高、不放大、不强制裁切、不用压缩预览图替代正式图。
- 缓存只保存视频索引、元数据、时间码、候选事实和脚本事实；缓存命中前仍检查视频哈希、Skill 版本、图像规则版本和脚本模板版本。
- 任何质量检查不通过，都不能直接复用旧的正式素材。

## 受控并行

- 默认并行度为 `min(4, max(1, CPU核数-1))`，同时保留 `--workers` 覆盖入口。
- 以“集”为最小并行单元；一集失败只重跑该集。
- 集内不得为同一个时间点重复启动 ffmpeg。先建立时间索引，再从原视频一次性提取需要复核的帧。
- 脚本裂变在剧情事实完成后并行；五个版本不重新读取视频。
- 写入使用临时目录和 checkpoint，单个包完成后再原子切换到正式目录。

## 内存控制

- 不把整部视频或全部帧加载进内存；使用流式读取和小批次任务。
- 每个 worker 只保留当前集的必要元数据和少量候选帧；完成后立即释放引用。
- 当可用内存低于安全阈值时，自动把新任务排队并降低并行度；不通过降低图片清晰度来换取速度。
- 缓存放磁盘，不放进常驻内存。缓存目录可清理，但清理后只影响速度，不影响质量。

## 缓存键

```text
视频内容 SHA256
+ 视频文件相对路径
+ Skill 版本
+ 图像规则版本
+ 脚本模板版本
+ 分析模型版本
```

安全模式下缓存命中必须重新确认源视频 SHA256；同时要求源视频存在、缓存 JSON 可解析、引用的源帧仍存在、质量规则版本一致。只有明确确认源文件不会被原地替换时，才允许用大小和修改时间快速命中缓存。否则该集进入增量重跑。

## 质量降级策略

遇到资源不足时，按以下顺序降级：

1. 减少并行 worker；
2. 降低同时排队的任务数；
3. 延后低置信度候选的精确复核；
4. 保留该集待复核状态。

禁止通过降低最终截图分辨率、删减脚本动作神态、减少时间精度或把多人图当单人物图来“提速”。
